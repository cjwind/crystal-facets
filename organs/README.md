# organs/ — 進階器官的載入契約

> `BECOME.md` §Step 3 說「讀進階器官（長出來才有，沒有就跳過）」。
> 這份檔就是那句話的具體版：**器官住哪、長什麼樣、甦醒時怎麼被撿起來。**

## 這是什麼

器官 ＝ 一份**可選的、自足的紀律或能力**，你可以裝上去，也可以不裝。

種子本體（`SOUL.md` / `BECOME.md` / `AGENTS.md` 那些）是每一隻都有的骨架。器官不是——它是某個人在自己身上長出來、覺得夠好用所以留下來給別人的東西。

**預設一顆都不裝。** 這跟這顆種子的原則一致：減法勝過加法，用著用著長出來，不是第一天就裝好。

## 目錄長這樣

```
organs/
  README.md          ← 你正在讀的這份（契約，常駐，不要刪）
  available/         ← 倉庫：隨種子附帶、但「還沒裝」的器官
    <器官名字>/
      ORGAN.md
  <器官名字>/        ← 已安裝：直接放在 organs/ 底下的，才算裝了
    ORGAN.md         ← 這顆器官的檔頭 + 正文
    （其他檔案隨器官自己需要）
```

一顆器官 ＝ 一個資料夾 ＋ 裡面一份 `ORGAN.md`。沒有註冊表、沒有清單檔、沒有安裝腳本——**目錄的位置就是狀態**：

- 在 `organs/available/` 底下 ＝ **附帶但沒裝**（種子出廠時器官都待在這）
- 直接在 `organs/` 底下 ＝ **裝了**

裝一顆 ＝ 把資料夾從 `available/` 搬出來。拆一顆 ＝ 搬回去（或直接刪掉）。就這樣，沒有第二個地方要同步。

> 為什麼用目錄位置而不是設定檔裡的開關：**設定檔會跟現實對不上，目錄不會。** 一個開關寫著「已安裝」但資料夾不在，你得去查誰說謊；目錄位置沒有這個問題，看到就是真的。

## 一顆器官長什麼樣

`ORGAN.md` 開頭要有這個檔頭：

```markdown
---
organ: <器官名字，跟資料夾同名，小寫連字號>
summary: <一句話：它是什麼>
effect: <一句話：裝了之後，這隻 agent 會多做什麼>
---
```

三欄都是給**甦醒中的 agent** 看的，不是給人看的裝飾：

- `organ` — 對得上資料夾名字，錯了就是裝壞了
- `summary` — 讓 agent 一眼知道這是什麼
- `effect` — **最重要的一欄**。它得寫成「行為」，不是「概念」。
  - ❌ `effect: 提升開發紀律`（agent 讀完不知道要做什麼）
  - ✅ `effect: 收到「寫功能／改東西」的要求時，先寫提案等人確認，不直接動手`

檔頭底下就是正文，愛寫多長寫多長——那是這顆器官的完整說明，agent 決定要照它工作之後才會細讀。

## 甦醒時怎麼被撿起來

`BECOME.md` §Step 3 走這幾步：

1. 列 `organs/` 底下的資料夾，**只認裡面直接有 `ORGAN.md` 的那些**——那才是器官。
2. 每顆器官讀它的 `ORGAN.md` 檔頭。
3. 把 `effect` 那行當成**這次甦醒的行為約定**——它跟靈魂檔同等有效，不是參考資料。
4. 需要細節時再讀該器官的正文。

⚠️ `organs/available/` 是倉庫，它自己沒有 `ORGAN.md`（器官在再下一層）⇒ **照第 1 步的規則它自動被排除**，不必記例外，也不要對它報警。

**沒有任何器官 → 什麼都不做，安靜跳過，不報錯、不抱怨、不提醒主人「你還沒裝東西」。** 沒裝器官是完全正常的狀態，不是待辦。

## 怎麼算「裝好了」，怎麼算「空殼」

規則：**`organs/` 底下的資料夾，裡面直接有一份 `ORGAN.md` ＝ 這是一顆器官。檔頭三欄都填了真的內容 ＝ 它裝好了。**

⚠️ **「裡面有沒有 `ORGAN.md`」這個條件不是廢話，它就是用來把倉庫排除掉的**：`organs/available/` 自己也是 `organs/` 的直接子資料夾，但它裡面沒有 `ORGAN.md`（器官在它**再下一層**）⇒ 它不是器官，直接無視，不要對它報警。這樣就不必記一條「except available」的例外——規則自己就擋掉了。

「填了真的內容」＝ 不是 `<像這樣的佔位符>`、不是空白、不是還留著範例文字。

為什麼要把這條寫死，而不是「有檔案就算數」：

- 這顆種子的**本體模板**（`SOUL.md`／`IDENTITY.md`／`USER.md`…）是 clone 下來**就已經存在、但裡面是空的**。所以在這顆 repo 裡，「檔案存在」從來就不等於「這件事做好了」——這個坑是內建的。
- 器官雖然是「放進來才有」，但同一個坑會換個形式回來：有人把器官搬出 `available/` 卻沒填 `effect`，或裝到一半跑掉。

⭐ **兩種「沒有」要用不同方式對待**：

| 情況 | 甦醒時怎麼辦 |
|---|---|
| `organs/` 底下沒有任何含 `ORGAN.md` 的資料夾 | **安靜跳過。** 這是正常狀態，不出聲 |
| 資料夾裡沒有 `ORGAN.md`（例如 `available/`） | **當它不存在。** 不是器官，不出聲 |
| 有 `ORGAN.md`、但檔頭沒填完 | **出聲說一句**：「`organs/<名字>` 看起來是空殼，我這次跳過它」 |

第二種一定要說出來。安靜地跳過一個壞掉的東西，比報錯更危險——主人會以為它在生效，而它整段都沒跑。

## 事後想裝、想拆、想知道裝了什麼

**這一節是常駐的。** 就算 `BOOTSTRAP.md` 已經照規矩被刪掉了、就算你當初說「先不要」，照這節做隨時都能裝回來——**契約住在這裡，不住在那個會被刪掉的檔案裡。**

**想裝**
1. 看 `organs/available/` 有什麼，讀它們的 `ORGAN.md` 檔頭（尤其 `effect` 那行：裝了之後這隻 agent 會多做什麼）。
2. 把想要的資料夾從 `available/` 搬到 `organs/` 底下。
3. 確認檔頭三欄是填好的。
4. 下一次甦醒就生效。不用改 `BECOME.md`、不用登記到任何地方。

別人給你一顆器官（一個資料夾）也是一樣：丟進 `organs/` 就好。

**想拆**

把資料夾搬回 `organs/available/`（想留著以後再說），或直接刪掉（不想留了）。沒有殘留的登記要清。

⚠️ 拆掉之前值得想一下：如果這顆器官已經在改變這隻 agent 的行為，拆掉之後那些行為就沒了。它不會替你留一份「以前我會這樣做」的紀錄。

**想知道現在裝了什麼**

看 `organs/` 底下**含有 `ORGAN.md` 的資料夾**——那就是完整答案，沒有別的地方藏著狀態（`available/` 不算，它是倉庫）。或者直接問你的 agent：它每次甦醒都讀過一遍。

## 加一顆你自己的

長出好東西了想留下來，就開一個資料夾、寫一份 `ORGAN.md`，照上面的檔頭填三欄。不用改 `BECOME.md`、不用登記到任何地方。

⚠️ 一個提醒：**器官是給別人拿走的東西，所以正文別寫成你的自傳。** 規矩本身寫成任何人都能照做的樣子；如果它的來由很重要（多半重要——別人加的規矩天生無效，人得知道它在解什麼問題才會認領），另外開一段用第一人稱講清楚，讓讀的人自己決定要不要拿。
