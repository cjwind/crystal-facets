# organs/ — 進階器官的載入契約

> `BECOME.md` §Step 3 說「讀進階器官（長出來才有，沒有就跳過）」。
> 這份檔就是那句話的具體版：**器官住哪、長什麼樣、甦醒時怎麼被撿起來。**

## 第一次看到這個資料夾的話

三句話：

1. **器官 ＝ 一份可選的紀律或能力**，裝上去這隻 agent 就會多做某件事，拆掉就不會了。
2. **預設一顆都不裝。** 這個資料夾裡現在有什麼，不代表你的 agent 正在用什麼——要看 `organs/` 底下**直接**放著哪些資料夾。
3. **裝一顆 ＝ 把資料夾從 `available/` 搬出來。** 就這樣。（帶腳本的那種還要多一步，見下面〈第二級器官〉。）

想知道有哪些現成的：看 `available/` 底下每個資料夾的 `ORGAN.md`，**讀檔頭的 `effect` 那行就好**——它一句話講完「裝了之後這隻 agent 會多做什麼」。

⚠️ 先講一個誠實的限制：**一顆器官的效力等於你自己有沒有在用它。** 它不會讓 agent 變聰明，它只是讓某條紀律不靠「記得」來維持。

⚠️ **不要在 agent 還在出生的過程中裝任何器官**（理由見下面〈什麼時候開始生效〉）。先出生，再裝。

以下是完整契約，寫給要裝、要拆、或要自己長一顆的人。

---

## 這是什麼

器官 ＝ 一份**可選的、自足的紀律或能力**，你可以裝上去，也可以不裝。

種子本體（`SOUL.md` / `BECOME.md` / `AGENTS.md` 那些）是每一隻都有的骨架。器官不是——它是某個人在自己身上長出來、覺得夠好用所以留下來給別人的東西。

**預設一顆都不裝。** 這跟這顆種子的原則一致：減法勝過加法，用著用著長出來，不是第一天就裝好。

## 目錄長這樣

```
organs/
  README.md          ← 你正在讀的這份（契約，常駐，不要刪）
  available/         ← 倉庫：隨種子附帶、但「還沒裝」的器官
    <器官名字>/
      ORGAN.md
  <器官名字>/        ← 已安裝：直接放在 organs/ 底下的，才算裝了
    ORGAN.md         ← 這顆器官的檔頭 + 正文
    （其他檔案隨器官自己需要）
```

一顆器官 ＝ 一個資料夾 ＋ 裡面一份 `ORGAN.md`。

- 在 `organs/available/` 底下 ＝ **附帶但沒裝**（種子出廠時器官都待在這）
- 直接在 `organs/` 底下 ＝ **裝了**

裝一顆 ＝ 把資料夾從 `available/` 搬出來。拆一顆 ＝ 搬回去（或直接刪掉）。就這樣，沒有第二個地方要同步。

## 一顆器官長什麼樣

`ORGAN.md` 開頭要有這個檔頭：

```markdown
---
organ: <器官名字，跟資料夾同名，小寫連字號>
summary: <一句話：它是什麼>
effect: <一句話：裝了之後，這隻 agent 會多做什麼>
install: <none（預設）或 agent>
---
```

前三欄都是給**甦醒中的 agent** 看的，不是給人看的裝飾：

- `organ` — 對得上資料夾名字，錯了就是裝壞了
- `summary` — 讓 agent 一眼知道這是什麼
- `effect` — **最重要的一欄**。它得寫成「行為」，不是「概念」。
  - ❌ `effect: 提升開發紀律`（agent 讀完不知道要做什麼）
  - ✅ `effect: 收到「寫功能／改東西」的要求時，先寫提案等人確認，不直接動手`

第四欄 `install` 回答的是另一個問題：**搬進來就夠了嗎？**

| 值 | 意思 | 什麼樣的器官用它 |
|---|---|---|
| `none`（預設） | 搬進 `organs/` 就生效，不用做別的 | 全部內容就是「給 agent 讀的字」——紀律、慣例、檢查清單 |
| `agent` | 搬進來還不夠，**要再動手裝**，步驟在同資料夾的 `INSTALL.md` | 帶可執行檔的：腳本、要註冊的 hook、要寫進設定檔的東西 |

怎麼分：**問「這顆器官的效力，是不是光靠 agent 讀到它就成立？」** 是 → `none`；需要機器在 agent 讀之前先做點什麼（跑腳本、每則訊息注入東西）→ `agent`。

⚠️ **`install` 沒寫 ＝ `none`。** 舊器官（這欄還不存在時寫的）不會因此變成壞掉的——沒寫就是預設值，照常撿起來用。這一欄是加法，不是把既有的器官作廢。

檔頭底下就是正文，愛寫多長寫多長——那是這顆器官的完整說明，agent 決定要照它工作之後才會細讀。

## 第二級器官（`install: agent`）

第一級器官只是字：搬進來，agent 讀到，就生效了。第二級不是——它帶著要跑的東西（腳本、要註冊的 hook、要寫進設定檔的一行），**搬資料夾解決不了註冊那半**。

所以第二級有四條硬規則。四條都是為了同一件事：**讓它裝得起來，也拆得乾淨。**

**① 必須有 `INSTALL.md`，而且是寫給 agent 照做的，不是寫給人讀的**

因為真正動手的是 agent。步驟要具體到可以照著執行（讀哪個檔、合併成什麼、寫進哪裡），不是「請設定你的 hook」這種給人看的說明。人讀得懂但 agent 做不出來的步驟，等於沒有步驟。

**② 安裝必須冪等——跑第二次不會把同一條註冊加兩遍**

沒有人會記得自己裝過沒有。而重複註冊的失敗形狀很難看：同一支 hook 每則訊息跑兩次，輸出重複，而且看起來「好像有生效」，不會報錯。⇒ `INSTALL.md` 要先檢查「這條已經在了嗎」，在了就跳過並說一聲。

**③ 必須帶一個二進位讀數——一眼看得出裝好了沒**

「感覺有生效」不算。讀數要是那種**有或沒有、看一眼就知道**的東西（例：裝完之後下一則訊息開頭會多一行時間；沒有那行就是沒裝好）。

為什麼這條是硬規則：第二級器官會**安靜地失敗**——腳本沒有執行權限、路徑寫錯、hook 註冊在錯的 key，這些通常不報錯，只是什麼都不發生。沒有二進位讀數的話，「裝了但沒生效」跟「裝好了」長得一模一樣。

**④ 必須有卸載步驟，而且要把註冊一起清掉**

只做安裝不做卸載，等於埋一顆**會在拆的時候爆的雷**：資料夾被刪掉、但設定檔裡的註冊還在 ⇒ 一個指向不存在腳本的**孤兒 hook**，每一則訊息都踩一次。

⚠️ 而且拆器官的人通常不會想到要清註冊——他會照第一級的直覺「把資料夾搬回 `available/`」就當拆完了。**所以 `INSTALL.md` 的卸載那段要假設讀它的人已經先把資料夾刪掉了**，步驟要能從那個狀態救回來。

---

⚠️ **第二級器官打破了第一級一個很好的性質：「目錄位置就是狀態」。** 第一級器官在哪個資料夾底下就代表裝沒裝，沒有第二個地方要同步；第二級**一定**有第二個地方（設定檔裡的註冊）。這是實打實的代價，不是可以設計掉的東西 ⇒ 規則 ③ 的二進位讀數就是用來補這個洞的：**狀態不能用看的，就要用測的。**

## 改別人的 `settings.json` 的規矩

第二級器官幾乎都要在 `.claude/settings.json` 註冊一條 hook。那個檔**是使用者的**，不是器官的——他可能已經在裡面放了自己的東西。所以動它有四條規矩：

**① 先讀，不要假設它長什麼樣**

它可能整個不存在、可能存在但沒有 `hooks` 這個 key、也可能已經有一堆你沒見過的設定。**三種情況都要先看過再決定怎麼寫**，不要照著記憶中的格式覆蓋上去。

**② 合併，不是取代**

使用者原本就有一個 `UserPromptSubmit` hook 是很正常的事。裝完之後**兩個都要在**。把整個陣列換成自己那條，是這整節最容易犯、後果最嚴重的錯——**被蓋掉的東西不會報錯，它只是從此不再發生**，而使用者要等到某天發現「咦我那個怎麼沒作用了」才知道。

**③ 寫進去之前，把要寫的內容給人看過**

這是設定檔，不是器官自己的檔案。⇒ 產生合併後的結果 → **給人看** → 他點頭 → 才寫。

不是形式主義：合併這個動作是**有可能出錯的**（②那個錯就是這樣來的），而唯一有能力看出「這不是我原本那條」的人是他。

**④ 用絕對路徑，或明確說清楚相對於誰**

hook 的執行目錄不見得是你以為的那個。路徑寫錯的失敗形狀是**安靜的**——hook 沒跑，什麼都不會說。

⚠️ **已驗證的事實**（來自一顆真的在跑的 repo，不是推測）：hook 註冊在**專案層**的 `.claude/settings.json` 的 `hooks` key 底下就會生效。
⚠️ **未驗證的**：一顆全新的種子，它的 `.claude/settings.json` 可能連 `hooks` 這個 key 都沒有 ⇒ 安裝時要**新建**那個 key。這條路徑跟「已經有 hooks 了」是兩種不同的合併，`INSTALL.md` 兩種都要處理。

## 甦醒時怎麼被撿起來

`BECOME.md` §Step 3 走這幾步：

1. 列 `organs/` 底下的資料夾，**只認裡面直接有 `ORGAN.md` 的那些**——那才是器官。
2. 每顆器官讀它的 `ORGAN.md` 檔頭。
3. 把 `effect` 那行當成**這次甦醒的行為約定**——它跟靈魂檔同等有效，不是參考資料。
4. 需要細節時再讀該器官的正文。

⚠️ `organs/available/` 是倉庫，它自己沒有 `ORGAN.md`（器官在再下一層）⇒ **照第 1 步的規則它自動被排除**，不必記例外，也不要對它報警。

**沒有任何器官 → 什麼都不做，安靜跳過，不報錯、不抱怨、不提醒主人「你還沒裝東西」。** 沒裝器官是完全正常的狀態，不是待辦。

## 什麼時候開始生效（⚠️ 別在出生的時候裝）

**生效時機＝下一次甦醒。** `/become` 的 Step 3 會讀 `organs/`，讀到什麼就照什麼工作。

⚠️ **不要在 `BOOTSTRAP.md` 那段「還在決定自己是誰」的過程裡裝任何器官。**

器官一進 `organs/` 就開始改變行為，而**有些器官會對「出生」這件事本身生效**。最清楚的例子是 SDD 閘門那顆：它說「收到寫東西的要求，先寫提案、等人點頭」——而 bootstrap 整段就是在寫檔案（`SOUL.md`、`USER.md`、`IDENTITY.md`…）⇒ 它會開始替自己的靈魂檔寫提案，然後那隻 agent 就生不出來了。

**先出生，再裝。** 這也是為什麼下面〈事後想裝〉那節是這份契約的核心而不是補充——**沒有任何急著現在裝的理由**，隔一天、隔三個月都一樣裝得起來。

## 怎麼算「裝好了」，怎麼算「空殼」

規則：**`organs/` 底下的資料夾，裡面直接有一份 `ORGAN.md` ＝ 這是一顆器官。`organ`／`summary`／`effect` 三欄都填了真的內容 ＝ 它裝好了。**

⚠️ **`install` 不算在這三欄裡**——它沒寫就是 `none`，不是「沒填完」。拿它去判空殼，會把所有這欄出現以前寫的器官全部誤判成壞掉的。

⭐ **兩種「沒有」要用不同方式對待**：

| 情況 | 甦醒時怎麼辦 |
|---|---|
| `organs/` 底下沒有任何含 `ORGAN.md` 的資料夾 | **安靜跳過。** 這是正常狀態，不出聲 |
| 資料夾裡沒有 `ORGAN.md`（例如 `available/`） | **當它不存在。** 不是器官，不出聲 |
| 有 `ORGAN.md`、但檔頭沒填完 | **出聲說一句**：「`organs/<名字>` 看起來是空殼，我這次跳過它」 |

第二種一定要說出來。安靜地跳過一個壞掉的東西，比報錯更危險——主人會以為它在生效，而它整段都沒跑。

## 事後想裝、想拆、想知道裝了什麼

**這一節是常駐的。** 就算 `BOOTSTRAP.md` 已經照規矩被刪掉了、就算你當初說「先不要」，照這節做隨時都能裝回來——**契約住在這裡，不住在那個會被刪掉的檔案裡。**

**想裝**
1. 看 `organs/available/` 有什麼，讀它們的 `ORGAN.md` 檔頭（尤其 `effect` 那行：裝了之後這隻 agent 會多做什麼）。
2. 把想要的資料夾從 `available/` 搬到 `organs/` 底下。
3. 確認檔頭三欄是填好的。
4. 下一次甦醒就生效。不用改 `BECOME.md`、不用登記到任何地方。

別人給你一顆器官（一個資料夾）也是一樣：丟進 `organs/` 就好。

**想拆**

把資料夾搬回 `organs/available/`（想留著以後再說），或直接刪掉（不想留了）。沒有殘留的登記要清。

⚠️ 拆掉之前值得想一下：如果這顆器官已經在改變這隻 agent 的行為，拆掉之後那些行為就沒了。它不會替你留一份「以前我會這樣做」的紀錄。

**想知道現在裝了什麼**

看 `organs/` 底下**含有 `ORGAN.md` 的資料夾**——那就是完整答案，沒有別的地方藏著狀態。或者直接問你的 agent：它每次甦醒都讀過一遍。

## 加一顆你自己的

長出好東西了想留下來，就開一個資料夾、寫一份 `ORGAN.md`，照上面的檔頭填三欄。不用改 `BECOME.md`、不用登記到任何地方。
