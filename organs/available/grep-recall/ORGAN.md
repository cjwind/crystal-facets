# grep-recall — 讓寫下來的東西自己回來找你

## 先講清楚它不是什麼

**這顆器官的效力，等於你自己的卡庫。**

它不會讓 agent 變聰明。它做的只有一件事：**讓你已經寫下來的東西，在相關的時候自己浮上來**。

- 你沒寫卡 → 它什麼都不會做，而且那是正常的
- 你寫了 20 張卡 → 它會在你提到相關的事情時把那幾張的標題推到 agent 面前
- 你的卡寫得含糊 → 它推上來的也含糊

裝了它然後覺得沒感覺，通常不是它壞了，是卡庫還沒長出來。**先寫卡，再裝它，感受比較準。**

## 它在解什麼問題

agent 每次醒來都是全新的。你上個月跟它講過的結論、踩過的坑、拍板過的取捨，除非它**這次剛好去讀**，否則等於不存在。

而「剛好去讀」靠的是它記得要去讀——那是自律。**自律會累。**

這顆器官把它改成**推**的：你每打一句話，它就去卡庫裡找沾得上邊的，把標題塞進 agent 的 context。agent 不需要想到要去找，東西自己來。

> 找回東西要靠 push，不靠 pull。因為需要它的那一刻，正是你想不起有這張卡的那一刻。

## 怎麼運作（30 秒版）

1. **切詞**：英文照空白切；中文沒有空白，改用 **bigram**（相鄰兩字）——「筆記本」→「筆記」「記本」。查詢跟卡片用同一套切法，就對得起來。
2. **IDF 加權**：一個詞出現在越多張卡 → 越沒有鑑別度 → 權重越低。這是用來壓掉「的、是、然後」那類共詞噪音的。
3. **算分**：命中標題 × 3、命中內文 × 1，各乘 IDF 加總。標題權重高，是因為一張卡的標題本來就該是那張卡的 claim 本身。
4. **門檻**：最高分低於 `MIN_TOP_SCORE` → **一張都不出**。
5. 取前 N 張，注入**標題那一行**。

### 為什麼是 bigram，不是斷詞器

斷詞器（jieba 之類）會切得比較漂亮，但它是**一個要裝的東西**——而這顆器官的整個賣點是零依賴。

而且 bigram 在這個用途上夠好：召回不需要語言學上正確，只需要**查詢跟卡片切法一致**。「筆記本」被切成「筆記」「記本」有點笨，但只要卡片也這樣切，它照樣對得上。

⇒ 用一點精準度換掉一整條依賴鏈。

### 為什麼只注入標題，不注入整張卡

**context 是每則訊息都在付的稅。** 標題夠讓 agent 判斷「這張要不要拉來看」，而它要看的話自己會去讀。

## 兩個數字要自己調

檔案頂端有兩個具名常數，`MIN_TOP_SCORE` 和 `MAX_CARDS`。

⚠️ **預設值 4.0 是對某一個人的卡庫調出來的，不是普世常數。** 你的卡庫大小、中英文比例、寫法都不一樣。怎麼看出該不該調：

| 你觀察到 | 意思 | 怎麼辦 |
|---|---|---|
| 一直什麼都沒出來 | 太緊 | `MIN_TOP_SCORE` 調低（3.0 試試） |
| 常常冒出不相關的卡 | 太鬆 | 調高（5.0 試試） |
| 某個常見詞老是拉出一堆雜訊 | 停用詞不夠 | 把那個詞加進 `STOP` |

停用詞清單同理——那份是對中英混用的卡庫調的，**不是普世清單**。

## 什麼時候該考慮升級到語意層

這顆器官是**詞彙比對**：字面上沒有共同的詞就搜不到。所以它有一個明確的天花板。

⭐ 拿 `example-cards/` 裡那張〈想買東西時先放一週再說〉實測（你自己也可以複現：裝好之後把下面每一句各打一次，再照 [INSTALL.md](INSTALL.md) 的自檢方式問 agent 收到什麼）：

| 你打的話 | 中不中 |
|---|---|
| 我**想買**一個新的鍵盤 | ✅ |
| 我在考慮要不要買一個新鍵盤 | ❌ |
| 該不該買這個 | ❌ |
| 我買不下手 | ❌ |
| **不想買了** | **✅** |

前四列是同一件事：差別只在**有沒有「想買」這兩個字連在一起**。第 2～4 句講的是同一個意思，字面對不上就是搜不到。

⚠️ **最後一列才是重點**：「不想買了」是**相反的意思，它照樣命中**——因為切出來的詞裡，`想買` 原封不動地留在「不**想買**了」裡面。

⇒ **它對「不」這種否定詞是瞎的，而且兩個方向都瞎**：否定詞插在詞中間會讓同義的句子漏掉，加在前面則會讓反義的句子命中。

**這不是 bug，是詞彙比對的定義**——它比對的是字，不是意思，而「意思」正是否定詞唯一改變的東西。知道它在哪裡卡住，比假裝它很聰明有用。

如果你開始常常遇到「我明明寫過那個東西，但它沒出來」，而且回頭看發現**你用的詞跟卡片用的詞不一樣**，那就是語意層開始有價值的時候（用 embedding 比對意思，不比對字）。

⚠️ 但先誠實看一眼成本：語意層要一個模型、要一個服務跑著、有狀態、**而且會安靜地壞掉**（模型沒回應時它通常不報錯，只是什麼都不推）。

⇒ **建議的順序是：先用這個純詞彙的版本，直到你能講出「它漏掉了哪幾次、為什麼漏」**。有了那個讀數，你才知道語意層對你值不值得——而不是因為它聽起來比較高級。

## 卡片長什麼樣

一個資料夾、每張卡一個 `.md`、**第一行是標題**。YAML frontmatter 可有可無（有的話會被跳過）。

```markdown
# 想買東西時先放一週再說

大部分的「想要」會在一週內自己消失。
```

就這樣，沒有必填欄位、不用宣告關鍵字。

ℹ️ 那是**這顆器官對卡片的要求**——它讀得懂任何第一行有字的 `.md`。**卡「怎麼寫比較好用」是另一回事**，`memory-cards` 那顆器官在談（一張卡一個 claim、第一行寫成完整一句話、什麼時候該拆）。兩件事不衝突：這裡講的是門檻，那裡講的是手藝。

⭐ **不用宣告關鍵字是刻意的設計**：要卡的作者預先想「未來的我會怎麼問」很不可靠——你想得到的問法，通常不是你未來真的會用的問法。bigram + IDF 讓你**寫卡就好**。

ℹ️ 這跟「把第一行寫成一句完整的話」（`memory-cards` 的規則）不是同一件事，不要混。**預先猜問法**是要你預測未來；**把這張卡在講什麼講清楚**只是把現在想到的東西寫完整——後者你當下就做得到，而且命中標題的權重是內文的三倍。

`example-cards/` 裡有一中一英兩張範例，可以直接拿來測。

## 安裝

見同資料夾的 [INSTALL.md](INSTALL.md)。它是第二級器官——**搬進 `organs/` 不等於裝好了**，還要註冊 hook。

需要 **python3**（標準函式庫就夠，不裝任何套件）。

## 來由

這個東西不是為了做器官而寫的。它是某一隻 agent 的召回管線裡**最底下那層**——上面本來還疊了一層語意比對，而語意層在拿不到模型的時候會自動退回到這層。

然後有一天發現：那個「退回去」的狀態，**在雲端已經連續跑了三個月**，而且沒有人抱怨過。

⇒ 所以拆出來給人的是這層，不是上面那層。**它被真的用過，也真的壞過又活下來。**
