# memory-cards — 一張卡，一句話，一件事

## 兩層模型

種子出廠時，長期記憶是一份檔：`MEMORY.md`，分節填空。這顆器官把它拆成兩層。

| 層 | 是什麼 | 角色 |
|---|---|---|
| `MEMORY.md` | **索引** | 開機入口。依主題分組，每張卡列一行：一句話標題 ＋ 連結。冷啟動讀它 ＝ 拿到全部 gist |
| `memory/cards/*.md` | **原子卡** | 一張卡 ＝ 一個完整的 claim。要細節時才拉那一張出來讀 |

換句話說：**`MEMORY.md` 從「內容」變成「目錄」。** 內容搬進卡裡。

### 日記不在這套裡

每日日記（`memory/YYYY-MM-DD.md`）維持流水帳，不用原子化。

原子化只發生在「日記 → 沉澱」那一步：某件事過了幾天還站得住、還會被用到，才把它切成一張卡。當天發生的事全部直接記進日記，不要一邊記一邊想「這該切成幾張卡」——那會讓你不想記。

## 一張卡長怎樣

```markdown
<第一行：完整一句話的 claim。這行就是這張卡的標題>

<body：能脫離脈絡單獨看懂。寫給「未來不記得前後文的自己」看>

相關: [[另一張卡的檔名]]、[[再一張]]
```

四條規則：

**① 第一行 ＝ 完整的一句話**

不是「關於睡眠」這種主題詞，是「開燈到睡著之間至少要留四十分鐘」這種**講完一件事**的句子。

判準跟寫 function name 一樣：名字要反映它做什麼。**能用一句話講完 ＝ 這張卡夠原子。**

⚠️ **第一行不能空著**，也不要用空行開頭。開頭寫 `# ` 可以（會被剝掉），不寫也可以——重點是**第一行就得是那句話**。

**② body 自足**

拿掉所有連結、離開原本的對話脈絡，還讀得懂。因為讀它的那個人（或 agent）不會記得當初為什麼寫下它。

**③ 檔名 ＝ 標題壓成的 slug**

放 `memory/cards/<檔名>.md`。一張卡兩個名字：第一行是可讀的全句，檔名是短把手。

**④ 連結用 `[[檔名]]`**

用檔名（不含 `.md`），不是第一行那句全文——這樣連結對得到檔。

⚠️ **誠實講一句**：`[[...]]` 是寫給人和 agent 讀的，**不會讓自動召回變準**。像 `grep-recall` 那種按詞比對的工具不解析連結，`[[foo]]` 在它眼裡只是內文的一串字。連結的用處是「順著讀下去」和「之後想寫工具時對得到檔」，不是加分項。所以有就連，沒有不勉強。

## 卡片可以有 frontmatter

檔案開頭可以放 YAML frontmatter（`---` 夾起來那段），讀卡的工具會跳過它再取標題。

想放「最後查驗日期」「來源」「信心度」這類機器讀的欄位時再長出來，一開始不用。**不要為了加 metadata 而加**——一張卡最重要的還是第一行那句話。

## 什麼時候該拆卡

跟拆 function 同一套標準：

- 一張卡只講**一件事**。
- **一句話的標題講不完它的內容** → 它在做兩件事 → 拆。
- 標題要用「而且」「另外」才接得下去 → 拆。

反過來也要看：**別過度原子化。** 切到「半句話、單獨看沒有意義」就太碎了——function 太小也是壞味道。判準是「拿掉脈絡還讀得懂嗎」，不是「夠不夠短」。

⭐ 這條規則的理由：按詞比對的召回工具（例如 `grep-recall`）**命中標題的權重比命中內文高好幾倍**。一張什麼都寫的長卡，查詢的詞多半落在內文裡、標題沒中 ⇒ 只拿得到低分 ⇒ 過不了門檻 ⇒ **它明明相關，卻永遠不會被推上來。**

## 跟種子原本的 `MEMORY.md` 是什麼關係

⚠️ **這顆器官跟大多數器官不一樣：它不是加一件事，它是修改既有的一層。**

種子出廠的 `MEMORY.md` 是一份**分節填空的大表單**（About My Human／Patterns／Frameworks…），`AGENTS.md` 也寫著「定期把日記 distill 進 `MEMORY.md`」。那套自己是成立的，這顆器官提供的是另一種形狀。

| | 種子原本 | 裝了這顆之後 |
|---|---|---|
| 長期記憶住哪 | `MEMORY.md` 一份檔 | `memory/cards/` 一堆小檔 |
| `MEMORY.md` 的角色 | 內容本身 | **索引**：每張卡一行標題 ＋ 連結 |
| 怎麼讀 | 整份載進 context | 讀索引拿 gist，要細節才拉那一張 |

### 不裝的人完全不受影響

沒把這個資料夾搬進 `organs/`，種子照原本的方式運作，什麼都不會變。這顆器官不會自己生效，也不會去改任何既有的檔。

### 已經有內容想遷移的話

不用一次搬完，也不建議一次搬完。

1. **`MEMORY.md` 先不要動。** 讓它照舊活著。
2. **從今天起，新的耐久結論寫成卡。** 卡庫從 0 張開始長。
3. **舊內容遇到才搬**：哪天翻到 `MEMORY.md` 裡某一條、發現它其實是一個獨立的 claim，那時候再把它切出來變一張卡，並在 `MEMORY.md` 原地換成索引那一行。
4. 等 `MEMORY.md` 裡剩下的都是索引行了，它就自然變成索引檔了。**沒有一個要一鼓作氣完成的搬家日。**

⚠️ 這幾步是一個可行的走法，不是唯一解。你想直接重寫 `MEMORY.md` 也可以。

⚠️ 種子還有**兩顆 skill** 也會往 `MEMORY.md` 寫東西——見下面〈跟骨架那兩顆 skill 是什麼關係〉。

## 什麼時候沉澱

**收工的時候。**

種子自帶的 `after-action` skill 就是那個位置——它的觸發詞是「收官／歸檔／wrap up」，做的事是回顧這輪發生了什麼、抽出教訓、寫檔。這顆器官只改其中一件事：**抽出來的耐久結論寫成卡，不是灌進 `MEMORY.md`。**

⭐ **不需要去掛任何排程。** 收工這個動作本來就會發生，沉澱搭它的便車。

⚠️ 種子另外自帶一顆 `self-evolution` skill，它的 frontmatter 建議用 `/schedule` 或 cron 掛成每晚跑。**那是加分項，不是這顆器官的前提**——想掛的人去看 `HEARTBEAT.md`，那邊已經寫了怎麼掛，這裡不重寫一份（兩份講法一定會漂移）。

> **為什麼落點是「收工」而不是「每晚」**
>
> 「每晚」需要一個**在 agent 沒開著時也會動**的東西，而那種東西一定住在使用者的環境裡：雲端 routine 綁使用者帳號、而且多半要 repo 已經在 GitHub 上；OS 的 cron 要機器開著，Windows 還沒有。**兩種都不在 repo 裡，器官塞不進去。**
>
> 收工不一樣：那個時刻 agent 還活著、檔案都在手上，什麼都不必先裝。

## 跟骨架那兩顆 skill 是什麼關係

種子自帶的 `self-evolution` 與 `after-action` 都會寫長期記憶，而它們寫的是**種子原本的形狀**——沉澱物直接進 `MEMORY.md`。裝了這顆器官之後，那幾句話要換一種讀法。

⛔ **不要去改那兩個檔。** 它們是骨架的核心檔，改掉之後上游的更新就吃不到了。下面這張表是拿來對照的，不是拿來當 patch 用的：

| 檔案 | 位置 | 它原本說 | 裝了這顆之後讀成 |
|---|---|---|---|
| `self-evolution/SKILL.md` | §Separate concerns | `MEMORY.md = what happened, what was learned` | `MEMORY.md` ＝ **卡的索引**；「發生了什麼、學到什麼」的內容住在 `memory/cards/` |
| `self-evolution/SKILL.md` | §Update Order 鏈上的 `→ MEMORY.md (memory snapshot)` | 更新 `MEMORY.md` | 拆成兩個動作：**先寫／更新那張卡**，再回 `MEMORY.md` 加或改索引那一行 |
| `after-action/SKILL.md` | §Step 3: Archive 第 2 項 `Long-term memory` | 重要的事寫進 `MEMORY.md`（新認知突破／重要決策與脈絡／系統性改變） | 那三種東西**各自成一張卡**放進 `memory/cards/`，`MEMORY.md` 只多索引那幾行 |

⭐ **同一節的第 1 項 `Daily log` 不用改**——它說日記寫進 `memory/YYYY-MM-DD.md`，跟上面〈日記不在這套裡〉本來就一致。⇒ 別因為第 2 項要改讀法，就以為整個 Step 3 都要重寫。

⚠️ **已經裝過這顆器官的人**：這一版改的全是文件，**下次甦醒讀到就生效**，不用重裝、不用跑任何步驟。（這是一級器官的好處：沒有第二個地方要同步。）

## 一個 claim 後來被推翻了怎麼辦

**就地標，不要改掉，也不要刪掉。**

在舊的那張卡上留一句：

```markdown
⚠️ 已更正（2026-08-16）：見 [[新的那張卡]]
```

為什麼不直接改掉：一個過時的值如果被安靜地改成新值，你就失去了「它曾經是別的樣子」這件事——而下次同樣的誤會發生時，你會需要它。

為什麼不刪掉：召回工具會把卡片的**標題**推到 agent 面前。一張標題看起來像事實、內容卻已經過時的卡，是最危險的一種——它會被當成事實引用。留著並標明，比刪掉安全，也比默默改掉誠實。

## 誠實的限制

**這顆器官不會替你寫卡。**

它只是一份慣例——講清楚卡長什麼樣、什麼時候該拆、怎麼標更正。實際去寫的是你（或你叫 agent 幫你寫）。卡庫空著的話，這顆器官等於沒裝。

它也不會讓 agent 變聰明。它做的事是：**讓你已經想清楚的東西，用一種之後找得回來的形狀存下來。**

## 一張卡長這樣（可以照抄的最小範例）

檔名 `開燈到睡著之間至少要留四十分鐘.md`：

```markdown
開燈到睡著之間至少要留四十分鐘

不是「早點上床」，是「亮的光要早點關掉」。試過幾次：關燈躺著滑手機，
跟提早四十分鐘把主燈換成小燈，後者明顯比較快睡著。

⇒ 所以要動的是燈，不是上床時間。

相關: [[睡不著的時候先看環境]]
```

三個地方值得看：

1. **第一行就是那句 claim**，不是「關於睡眠」這種主題詞。
2. **body 自足**——沒有前後文也讀得懂，因為它自己交代了「試過什麼、所以結論是什麼」。
3. **連結有就連**。`[[睡不著的時候先看環境]]` 就算還沒寫，寫著也沒關係——它標的是「這裡有一張值得寫的卡」，不是錯誤。
